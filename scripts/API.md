# TravelBook Studio API

`backend/app/main.py` provides a FastAPI application backed by the existing SQLite database and artifact records. Its factory accepts isolated settings/database instances for testing. Database initialization occurs during application startup.

## Start on Windows

From the project root, with the virtual environment activated:

```powershell
python -m pip install -e .
python -m backend.app.main
```

The module uses `APP_HOST` / `APP_PORT` from Settings (defaults `127.0.0.1:8000`). Alternatively:

```powershell
python -m uvicorn backend.app.main:app --host 127.0.0.1 --port 8000
```

Open http://127.0.0.1:8000/docs for Swagger **Try it out**. OpenAPI JSON is at `/openapi.json`; `/health` checks database connectivity. Swagger's default JavaScript/CSS assets load from its CDN, so the browser needs access to that CDN. CORS allows the configured `FRONTEND_ORIGIN`. This is the local application API, without an authentication layer.

## Endpoints

| Method | Path | Result |
| --- | --- | --- |
| POST | `/api/projects` | 201, saved brief/initial State and Location header |
| GET | `/api/projects?limit=20&offset=0` | Project summaries with pagination and total |
| GET | `/api/projects/{project_id}` | Project, State, optional TripRequest, tasks |
| GET | `/api/projects/{project_id}/events?after_id=0&limit=100` | Events in increasing ID order, next_after_id cursor |
| GET | `/api/projects/{project_id}/artifacts?limit=20&offset=0` | Artifact metadata, evidence and download URLs |
| GET | `/api/projects/{project_id}/artifacts/{artifact_id}` | One artifact belonging to that project |
| GET | `/api/projects/{project_id}/artifacts/{artifact_id}/download` | Original file bytes as an attachment |
| DELETE | `/api/projects/{project_id}?delete_files=true` | 204, remove project and related records/files |

IDs must contain only letters, digits, underscores or hyphens and be at most 100 characters. Project IDs are generated by the server. Missing resources return 404; invalid bodies/parameters return 422; unsafe downloads return 403; active projects or deletion conflicts return 409.

## Test manually in /docs

1. Expand **POST /api/projects**, select **Try it out**, and submit:

```json
{
  "title": "Cẩm nang Đà Nẵng",
  "prompt": "Đà Nẵng 3 ngày cho một người, ngân sách 5 triệu đồng",
  "trip_request": null
}
```

2. Copy the response `id` into **GET /api/projects/{project_id}**. Check status `queued`, the saved `user_prompt` in State and the project_created event.
3. Test **GET /api/projects**, events and artifacts. A new project has no artifacts until agents create them.
4. For a standalone file-download demo, run this separate command in the same environment/database:

```powershell
python scripts/check_api.py --seed
```

It creates one clearly labeled fixture project and a research.json artifact, and prints their IDs. Use those IDs in the artifact-list/detail/download endpoints. Existing projects created by previous agents are also visible in the same database; their generated PDFs/PNGs/JSON can be downloaded through their own artifact IDs.

5. Delete only your test project with **DELETE**. The response is empty with status 204. Subsequent detail/events/artifact requests return 404.

Creating a project stores the brief. The optional `start_workflow=true` flag starts the current fixture graph; the frontend supplies this when “Chạy ngay sau khi tạo” is selected. Run/pause/resume/stop controls and human approval gates are available; see WORKSPACE_UI.md. Events use cursor polling, not SSE.

## File and deletion behavior

Downloads resolve the registered local path and require it to remain inside that project's directory under `settings.artifacts_dir`. Requesting another project's artifact ID returns 404. Missing files return 404. Symlink escapes are rejected; no endpoint accepts an arbitrary file path for downloading.

Deleting a project cascades to its tasks, events and artifact metadata through SQLite foreign keys. By default it also removes only `artifacts_dir/<project_id>`. `delete_files=false` explicitly retains disk files while removing metadata; they are then inaccessible through this API. Root/reserved fixture directories and linked directories are protected from cleanup. The source fixture `danang_3days` cannot be removed through the normal file-cleanup path.

Running/pause_requested projects cannot be deleted. The delete transaction locks writers and rechecks current status before cleanup. If filesystem cleanup fails, the API returns 409 and retains metadata; a filesystem operation may already have removed some files before a later error, so disk and database cleanup are not a single atomic transaction.

## Automated checks

```powershell
python scripts/check_api.py
python -m unittest discover -s tests -p test_api.py -v
```

The default smoke uses ASGI HTTP transport and a temporary SQLite database, covering Swagger HTML/OpenAPI, creation/list/detail, events, artifact metadata, byte-exact downloads and cascading deletion. It writes `reference-review/api_validation.json`. No network server or LLM is required.

Delivery validation uses isolated ASGI tests. An attempted direct Uvicorn validation was blocked by automatic approval review because the process generated an unexpected telemetry connection to dc.services.visualstudio.com with an unknown payload. Live server/browser interaction was therefore not confirmed in this environment; no successful live /docs claim is made.
